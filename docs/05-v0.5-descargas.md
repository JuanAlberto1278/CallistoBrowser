# Callisto V0.5 — Descargas autorizadas y página de nueva pestaña

> Fecha: 2026-11-22 · Electron 45.4.1 (Chromium 156) · Estado: **completa, pendiente de tu revisión**

## Qué incluye

| Funcionalidad | Detalle |
|---|---|
| **Autorización antes de guardar** | Toda descarga se **cancela en el instante** en que Chromium avisa, y Callisto pregunta en un panel bajo el botón de descargas: nombre, tamaño, sitio y carpeta de destino. **Guardar**, **Guardar como…** (diálogo de Windows) o **Cancelar**. Hasta que elegís, no se guarda nada |
| Al autorizar | Callisto vuelve a pedir el archivo al sitio, con las cookies de la pestaña que lo inició, y lo guarda directo en la carpeta elegida |
| Formularios y enlaces de un solo uso | Si el sitio no deja repetir el pedido (formulario POST, enlace firmado), la descarga pasa a **"Volvé a hacer clic en el enlace"**: el próximo clic en ese archivo, durante 1 minuto, se guarda sin volver a preguntar |
| Varias a la vez | Se pregunta por cada una, en orden ("Hay 2 descargas más esperando") |
| Seguridad del pedido | Los botones se activan recién a los 400 ms y cada pedido es un elemento nuevo: un doble clic sobre "Guardar" nunca autoriza la descarga siguiente, que todavía no viste |
| Tipos peligrosos | `.exe`, `.msi`, `.bat`, `.ps1`, `.lnk`, `.iso`, macros de Office, etc. muestran "Este tipo de archivo puede dañar tu equipo" |
| Marca de Internet | Lo descargado recibe la marca *Mark of the Web* (`Zone.Identifier`), como en Chrome y Edge: Windows SmartScreen y Office advierten antes de abrirlo |
| Progreso | Botón de descargas con anillo de progreso; panel con barra, velocidad y tiempo restante |
| Pausar, reanudar, cancelar, reintentar | En el panel y en la página de descargas. Cancelar borra el archivo parcial |
| Abrir y mostrar en la carpeta | Clic en la descarga terminada la abre; el ícono de carpeta la muestra en el Explorador |
| Página de descargas (`callisto://downloads`, Ctrl+J) | Todas las descargas por día, búsqueda, quitar de la lista (el archivo no se borra), borrar la lista, abrir la carpeta. Se actualiza sola mientras hay descargas en curso |
| Carpeta configurable | Configuración → Descargas → **Cambiar…** (selector de carpetas de Windows). Por defecto, la carpeta Descargas |
| Nombres seguros | Caracteres no válidos, nombres reservados de Windows y las marcas invisibles que disfrazan la extensión (`factura‮fdp.exe`) se corrigen; si el nombre existe, se guarda como "archivo (1).pdf" sin pisar el anterior |
| Guardar imagen / enlace como… | En el menú contextual; el diálogo de Windows es la autorización |
| Pestañas abiertas solo para descargar | Un enlace `target=_blank` que solo descarga no deja una pestaña vacía (como Chrome) |
| Lista persistente | Las descargas quedan en la lista al reiniciar; lo que estaba a medias se marca "Callisto se cerró antes de que terminara" |
| **Página de nueva pestaña** | Saludo según la hora ("Buenas tardes") con la fecha, un buscador y tus **sitios más visitados** (uno por sitio, con su ícono; se pueden quitar con "Deshacer" y "Mostrar todos"). La dibuja la interfaz encima de la pestaña vacía: al escribir una dirección, la pestaña navega normalmente y conserva su historial |

## La garantía, con números

Criterio de cierre de V0.5: **la matriz de mecanismos de V0.1 pasa al 100 %**. Cada mecanismo se probó de punta a punta
en Callisto, tres veces:

| Mecanismo | Pregunta antes de guardar | Cancelar no deja nada | Guardar deja el archivo completo y exacto |
|---|---|---|---|
| Enlace con `Content-Disposition` | ✅ | ✅ | ✅ |
| `application/octet-stream` | ✅ | ✅ | ✅ |
| `<a download>` | ✅ | ✅ | ✅ |
| `location.href` por JavaScript | ✅ | ✅ | ✅ |
| `window.open` | ✅ | ✅ | ✅ |
| Redirección 302 | ✅ | ✅ | ✅ |
| Formulario POST | ✅ | ✅ | ✅ (volviendo a hacer clic) |
| iframe | ✅ | ✅ | ✅ |
| `blob:` vigente | ✅ | ✅ | ✅ |
| `blob:` revocado al instante ("Exportar CSV") | ✅ | ✅ | ✅ |
| `data:` | ✅ | ✅ | ✅ |
| PDF adjunto | ✅ | ✅ | ✅ |
| URL de un solo uso (enlace firmado nuevo en cada clic) | ✅ | ✅ | ✅ (volviendo a hacer clic) |
| Archivo de 20 MB | ✅ | ✅ | ✅ |
| Tres descargas simultáneas | ✅ | ✅ | ✅ |

"Exacto" significa que se compara byte a byte con lo que envió el servidor. Además se verificó que no queda nada en
Descargas, ni en la cuarentena privada, después de cancelar.

**Límite conocido (medido en V0.1, sin cambios):** mientras decidís, Chromium puede tener hasta ~512 KB (o un archivo
chico entero) en un temporal de la **cuarentena privada de Callisto**, nunca en una carpeta tuya. Al cancelar desaparece,
nunca se usa como resultado y la cuarentena se vacía al cerrar y al abrir Callisto.

## Decisiones importantes

### Un enlace de un solo uso *fijo* no se puede recuperar
Si un sitio pone en la página un enlace de descarga que vale **una sola vez** (siempre el mismo), el primer clic lo gasta,
aunque Callisto cancele la descarga al instante. Al autorizar, el sitio responde "vencido", y volver a hacer clic tampoco
sirve: hay que pedirle al sitio un enlace nuevo. Los enlaces firmados que se generan en cada clic, que son el caso común,
funcionan. Chrome no tiene este problema porque descarga sin preguntar: es el precio de no guardar nada sin tu
autorización.

### Página de nueva pestaña dibujada por la interfaz
La página de nueva pestaña no es una página web ni una pestaña interna: la interfaz la dibuja encima de la pestaña vacía.
Así, escribir una dirección navega **en la misma pestaña**, con su historial de atrás/adelante (una pestaña interna habría
tenido que reemplazarse). Solo la muestran las pestañas que abrís vos (Ctrl+T, +, ventana nueva); las que abre una página
no, así no aparece un instante antes de cargar un enlace.

### Las pruebas nunca tocan tu carpeta Descargas
Cuando Callisto corre con una carpeta de datos aislada (pruebas automáticas y verificación del ejecutable), las descargas
van dentro de esa carpeta aislada.

## Errores encontrados y corregidos durante V0.5

| Error | Causa y corrección |
|---|---|
| **"database is not open" otra vez** (en el título de una página) | La corrección de V0.4 cerraba la base en `exit`, pero Electron sigue emitiendo eventos de las páginas después de `exit` (títulos de páginas que terminan de cargar). Ahora la base **no se cierra explícitamente**: SQLite en modo WAL ya tiene a salvo todo lo confirmado y la base se cierra sola al terminar el proceso |
| Las pruebas dejaban ~170 procesos de Callisto abiertos, con diálogos de error | El error anterior trababa el cierre con un diálogo; la red de seguridad de las pruebas terminaba solo el proceso principal. Ahora termina el árbol completo, y **cualquier excepción del proceso principal hace fallar la prueba**: este tipo de error ya no puede pasar desapercibido |
| Un formulario POST repetido quedaba "interrumpido" en vez de pedir volver a hacer clic | Chromium no siempre da por terminada la descarga rechazada (405/410); ahora se detecta en el primer aviso de interrupción sin datos |
| Riesgo de autorizar sin querer la descarga siguiente | Botones activos recién a los 400 ms, cada pedido es un elemento nuevo |

## Limitaciones conocidas

| Limitación | Cuándo se resuelve |
|---|---|
| Enlaces de un solo uso **fijos** (ver arriba) | límite del diseño, documentado |
| Hasta ~512 KB en la cuarentena privada mientras decidís (ver arriba) | requiere modificar Chromium |
| "Guardar página como…" (Ctrl+S) | sin versión asignada |
| Reanudar después de reiniciar Callisto una descarga que quedó a medias (hoy: "Reintentar" desde cero) | sin versión asignada |
| En una carpeta FAT/exFAT o de red puede no ponerse la marca de Internet (esos sistemas no la admiten) | límite de Windows |
| La página de nueva pestaña no tiene fondos ni personalización (no se pidió temas) | — |
